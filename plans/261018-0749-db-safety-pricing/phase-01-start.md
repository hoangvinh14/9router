# Design / manifest / execution

## Chosen design
- Acquire exclusive writer namespace at the realpath of DATA_DIR's `db/` directory, before file open, backups, migrations and timers. Direct adapter factories acquire the **same database-parent namespace**, so they cannot bypass driver ownership; standalone temp-file fixtures get their own namespace. Creating the directory is allowed pre-lock, not database/maintenance mutation. Refuse symlink database files; canonical parent aliases share lock. Owned token verified by module-private WeakMap, not caller-supplied `assertOwned` functions.
- Atomic lock-file create and short acquisition arbitration directory. Lock contains PID/incarnation/instance, mode0600. Linux stale owner may be reclaimed only with same boot + ESRCH proof; malformed/PID reuse/unknown liveness/interrupted acquisition fail closed. No timeout-based unlock or manual deletion by application. Owner release only after adapter is closed and all callbacks removed; failed close keeps exclusion until verified process death/operator procedure.
- Driver fallback only after engine unavailability established **before application file open**. Probe better-sqlite3 on `:memory:` only (retain Node>=24 skip); project module errors/application open/PRAGMA/init failures are fatal. HMR process global persists adapter+promise; closed adapter resets owning singleton through lifecycle callback.
- Native shared wrapper verifies WAL/FULL at open and before durable commit; SAVEPOINT transaction depth tracked; synchronous callback/result only, outermost durable method; RELEASE/rollback uncertainty permanently poisons reads/writes/memo. Reject raw BEGIN/END/COMMIT/ROLLBACK/SAVEPOINT/RELEASE through every SQL entry point, including multi-statement exec; engine handles remain private so raw outer transactions cannot falsely ACK nested savepoints. Reject AsyncFunction before invocation; returned thenables roll back and poison to deny later escaped continuations. Do not expose unguarded raw handles (no current DB consumer uses them). Generic SQL remains internal/trusted, not a sandbox against hostile in-process modules. Raw transaction control is rejected; get/all accept single SELECT or allowed introspection PRAGMA only. Writes, including trigger installation, use managed run/exec and normal transaction/depth/dirty invalidation; WAL/FULL is reverified before native durable ACK. Adapter close removes checkpoint/shutdown callbacks before releasing ownership, never ACKs a failed transaction retroactively.
- SQL.js all writes share one image/coordinator. Ordinary mutations remain debounced; durableTransaction cancels pending timer and exports to same-directory0600 temp, fsync file, rename, fsync directory before success. Any publication error poisons and cancels timer; all reads/writes denied, close discards uncertain RAM without rewriting, reopening sees actual file and new lifetime. Rollback failures poison; dirty and transaction-local memo false. Health reports fresh ownership; close must remain possible after poison/lost ownership without flushing.
- Initialization performs migration then durable empty transaction before exposing adapter. No migrations/schema definitions copied from accounting; schema2/ACL unchanged. Existing migration backup uses SQL.js ATTACH virtual FS and does not create a host backup: add SQL.js `backupTo` clone/export using durable writer and have backup helper use it. This is the minimal actual safety-backup compatibility repair, not restore redesign.
- No platform support reduction is authorized. Filesystems unable to supply required durable ACK fail the durable operation explicitly (never silently lower durability); platform/runtime acceptance remains open until actually verified. Windows directory fsync behavior is unverified, so no blanket compatibility or release claim is allowed. Raw private engine handles stay closed over, guarded SQL API retained.

## Design review
Advisor flagged raw outer transaction false ACK, arbitration release races, hardlink/alias and backup-destination hazards. Implementation must reject raw transaction control, arbitrate release as well as acquire/reclaim, reject nonregular/symlink/multilink live files, use private owner tokens, and reject backup paths in the live parent namespace. Data directory must be trusted local same-host/same-PID-namespace; no hostile directory replacement/network-filesystem/cluster claim. Actual unavailable Bun/better and Windows remain acceptance limitations, not approved support removal. Direct review remains responsible; advice is not verification evidence.
