## Success evidence

**Restart after a committed terminal.** In the isolated C0 fixture, the writer receives the native JSON response and checks the durable policy and one 105,900 nanoUSD terminal. It is then killed with SIGKILL before SQLite can close. A fresh Node process reads the same policy and terminal, returns 503 at the persisted limit, and adds zero POSTs and zero terminals. Raising the limit by one nanoUSD admits exactly one POST and one further terminal. Counted transport and HTTPS loopback suites both passed 14/14 on Node v24.21.0. Crash points before terminal acknowledgement, startup migration, and the wider platform matrix remain open.

**Crash points around SQLite commit.** The C0 fixture kills the writer before intent COMMIT, after intent acknowledgement and before transport, after one POST and before reading the response body, after a complete response read but before terminal COMMIT, and immediately after terminal COMMIT before the application observes its acknowledgement. A fresh Node process sees respectively 0 intents and 0 terminals, 1 intent and 0 terminals, 1 intent and 0 terminals, 1 intent and 0 terminals, and 1 intent and 1 terminal for 105,900 nanoUSD. It preserves the saved policy, permits a new request when spend is below the limit, and refuses at equality without an extra POST or terminal. Both compose suites passed 19/19 on Node v24.21.0, including actual HTTPS loopback. Startup migration, restore, crashes that interrupt response reading, and the wider platform matrix remain open.

**Standalone backup restore.** The Linux Node SQLite fixture takes the app's lightweight backup at 3,000,000 nanoUSD spent and then advances the source policy and spend to 6,000,000 nanoUSD. The fixture copies only the backup database file into a new path and opens that copy with a new adapter. Its policy, recorded spend and stored attempts match the snapshot. The next request at its restored limit is refused with zero transport invocations and zero new terminals. Foreign-key and integrity checks pass. The source keeps its newer policy and spend. The backup suite passed 15/15. This verifies the SQLite accounting boundary for a standalone snapshot. Installed startup after restore and credential rollback policy remain open.

Exact test selectors/revision hashes+adapter/platform table; durable saved-row restart+zero-next-POST; original identity/price/window checks after late/concurrent controls; fault/migration roundtrip no known-truth loss; unresolved old timing/native-isolation gates either repaired with new causal evidence or exact owner disposition. Broad pass counts/baseline classifications alone do not grant completion. All runtime checks external sandbox only; see phase05.
