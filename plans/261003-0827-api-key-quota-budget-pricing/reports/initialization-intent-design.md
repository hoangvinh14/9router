## Future protocol requirements

1. Explicit healthy initializer under exclusive writer ownership creates a uniquely identified, bounded durable initialization intent **before** the irreversible sidecar transition. Capture committed state and retain ownership throughout capture→intent fsync ACK→transition→DB commit; no callback interleaving or check/use opening.
2. Versioned canonical **full logical committed snapshot** fingerprint: schema definitions (tables/indexes/triggers/views), every persistent table row with duplicate multiplicity and deterministic ordering, exact SQLite value types/text/blob bytes, database identity/migration/meta state, user_version/application_id and sequences as applicable. Explicit handling of rowid/virtual tables/unsupported objects and values; unsupported cases deny, never omit. Unrelated settings/history changes may conservatively block recovery.
3. Native snapshot through SQLite read transaction includes committed WAL. Main DB file hash alone is insufficient; logical hashing need not checkpoint WAL. SQL.js uses independent reopened durably persisted image; require live and persisted logical snapshots agree. No RAM-only proof.
4. Intent binds coverage ID, binding-key ID, unique operation, exact sidecar pre/post states, fingerprint algorithm version, deterministic transition payload and DB pre/post images. Insert ONLY missing policies using recorded deterministic timestamp and version0 BOTH-NULL, preserve restrictive/existing policies exactly. Receipt/audit must bind operation and payload.
5. Avoid circular postimage hash: any normalization must be precisely versioned, limited to that operation receipt's specific hash field, separately validate it against intent. Never exclude an entire audit/receipt table or ignore unrelated changes.
6. Explicit **offline operator** command only. Same exclusive owner lock before read-only inspection; no ordinary app DB initialization, migrations, policy inference or binding writes. Validate complete artifact set before narrowly scoped write phase and recheck exact preconditions. No normal-startup recovery.
7. Allow only intent+exact old sidecar+DB preimage (resume), intent+exact new sidecar+DB preimage (finish recorded transaction), intent+exact new sidecar+DB postimage+receipt (recognize already committed). Unknown/mixed/malformed/missing evidence denies without writes. Crash matrix must include intent uncertain ACK, sidecar uncertain ACK, DB commit before lost ACK and audit replay; Node and SQL.js real process tests remain required.
8. Keep intent and receipt as managed restore evidence; completion never silently accepts missing retained evidence. Bounds, validation, audit/actor and restore compatibility must be designed/tested before delivery.

## Trust/freshness limits

Advisor review of source summaries/excerpts—not independent patch approval—clarifies a full logical fingerprint proves an exact state match, **not freshness**. It rejects a stale same-coverage DB with differing contents; logically identical preimages are indistinguishable. Rollback of the entire DB/sidecar/intent bundle requires an external monotonic or append-only witness outside the restore domain to detect. Hashes do not authenticate against an administrator rewriting every artifact; filesystem/admin trust must be stated, or use independently protected authority. Intent creation cannot prove ledger/policies were never removed before the committed preimage was captured. Historical eligibility needs trustworthy history, not current absence.

External witness/authority is a consequential architecture choice, not silently introduced here. Current historical interrupted files therefore cannot safely be repaired to unlimited based on markers/empty tables alone.
