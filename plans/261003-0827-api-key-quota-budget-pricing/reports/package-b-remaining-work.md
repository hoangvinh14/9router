## Execution efficiency rules

1. **Outcome-sized work:** finish a named family/seam packet; avoid hopping between providers or adding one more synthetic fault repeatedly to an already validated slice.
2. **Test-first with source inspection:** reuse valid fixture builders/schema/normalizers to avoid preventable fixture failures. Distinguish setup errors from reached protocol assertions. Do not patch production to satisfy an incorrect fixture.
3. **Evidence reuse:** rerun only changed boundaries and affected consumers; broad impact once per coherent shared-code milestone. No repeated full successful lane merely for green counts. A previous receipt is reusable only if relevant source/input/environment is unchanged.
4. **Focused → actual boundary → one impact barrier:** choose relevant controls from the contract, not arbitrary combinations. Node/SQL.js repeats same unique controls. Native loopback is not live provider/TLS/powerloss certification.
5. **No weakening:** no changed1scollector, ACK/deadline/quorum/grace/money/durability assertions; no scheduler/reservations/new DB/Redis/spend cache/multiwriter. Keep completion errors outside transport catches.
6. **Clear stop/escalation:** if a required protocol fact is not observable/documented, report exact evidence blocker and seek a material decision rather than guess or run more irrelevant tests. Contract/support change needs user approval.
7. **Progress by delivery:** report active packet, implemented outcome, verified scope, remaining blocker and next closure action. Counts support claims, not percent complete or ETA. One source/test writer and one gate barrier; no polling just to wait.
