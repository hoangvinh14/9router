## Candidate persistence protocol (not implemented/evidenced)

Advisor pre-implementation review requires atomic lock reclamation, cross-file ordering, sync-only callbacks and independently reopened backups. Candidate ordering:

1. Canonicalize DATA_DIR and acquire exclusion before writable adapter creation. Lock publication must never be partially parsed/reclaimed as dead. Reclamation requires atomic arbitration and proven process death; unknown/liveness/PID reuse fails closed. HMR keeps the same process-global owner. Release only after adapter timers and writes stop.
2. Initialize protected binding material/coverage sidecar only for verified pre-activation installation. Sidecar identity must match durable database metadata. Persist sidecar first, then metadata reference; interrupted initialization is resumable only by matching identity, never by clean regeneration of active coverage.
3. Migration/bindings transaction acknowledges durable schema and historical binding/backfill, but no activation timestamp. Post-activation missing or mismatched artifacts fail closed.
4. Intent and settlement use sync transaction callbacks. SQL.js serializes current snapshot through same-filesystem temp file, file fsync, rename, directory fsync; uncertain acknowledgement permanently poisons adapter operations/timers until persisted reopen. Native WAL/FULL readback must pass before claiming durability.
5. Recovery reads sidecar generation G; DB commits matching operation/audit durably before sidecar CAS acknowledgement. DB failure preserves G; crash between audit and sidecar leaves blocked and replayable. New generation never cleared by stale recovery. Maintenance independent of gap acknowledgement.
6. Physical restore preserves current sidecar/binding material/tombstones outside the replaced snapshot, enters maintenance first and requires verified audited merge/reconciliation. Out-of-band rollback detection is not promised.

These are implementation candidates, not passing evidence. Review lock/crash protocol against concrete code and tests before accepting phase 01.
