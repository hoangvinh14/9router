## 4. Attempt, disposition và successor permission

| Evidence / point | Required result | Successor rule |
|---|---|---|
| Auth/ACL/profile/price/route/abort fails preintent | No POST/no fabricated charge | No successor from refused authority |
| Intent committed, dispatch fails before invocation | Own `not_dispatched` terminal ACK, zero POST | Reauthorize only through explicit normal flow; cannot consume receipt twice |
| Valid raw usage, HTTP2xx or failure | One exact settlement at original price/time; own terminal ACK | May fallback only if normal status policy allows and fresh budget/authority passes |
| Interrupted network/body read with no usage evidence | B1 durable `unrecorded`, no invented cost, nonblocking | Only if cancellation/status policy permits; aborted client must not cause successor |
| Complete JSON/error without usage | `unresolved`, safety refusal | Terminal ACK alone insufficient: no successor |
| Malformed UTF8/JSON/usage, duplicate keys, conflicting counters, observed partial usage or oversize | Preserve invalid evidence disposition; `unresolved`, never absent/zero | No successor, even if HTTP fallback-eligible |
| Terminal publication or own ACK failure | Existing fail-closed recording protocol; own gap ACK where applicable, retain key/binding safety | No retry/account advance from a copied row or receipt |
| Late same usage / conflict | Idempotent no second debit; conflict retains known charge+safety | No authority resurrection after dispose/revoke |

Precedence: already observed malformed/conflicting/oversize evidence always wins over later interruption; a fully validated complete JSON document with valid usage settles even if the caller aborts afterward. For this bounded JSON owner, transport abort/error/timeout **before any body bytes** with no invalid evidence is interrupted+absent→`unrecorded`; bytes that form an incomplete JSON document at abort, read error or premature EOF are observed partial/malformed→`unresolved`, even when usage has not yet appeared. No successful parser completion may be inferred from reader failure. A fully received zero-byte response or complete JSON without usage is complete+absent→`unresolved`, regardless HTTP status. Local size-limit termination is malformed/unsupported→`unresolved`, never the B1 exemption. Required named tests: abort before headers, abort after headers with zero bytes, abort mid-JSON before/inside usage, premature EOF, above-cap cancellation, complete missing usage, complete valid usage before abort. This is conservative classification of observed partial JSON, not a change to B1's genuine interrupted+absent rule. Settlement validity and provider request success are independent. Callback/success logger follows own accounting completion, never makes failed attempt successful.

**Client-visible error contract (Validation Session1):** keep existing account-fallback eligibility and narrow bookkeeping. A selected upstream HTTP error with valid exact usage, after its own terminal ACK, retains original HTTP status and raw JSON body bytes if it is ultimately returned, including no-more-accounts/all-rate-limited branches. Preserve at raw boundary AND through core/entry, not only in accounting evidence. Later successful account returns its own response; never expose an intermediate error instead. Budget/authority/accounting-recording refusals have precedence and must not be hidden by a retained upstream error. Preserve only upstream `Content-Type`; local CORS/no-store/request-id headers remain locally owned. Do not forward upstream authorization, cookies, Location, hop-by-hop, Content-Length or Content-Encoding headers (fetch may already decode bytes). Keep at most the currently needed bounded final-error payload in request-local memory and release superseded bytes; no ledger/receipt persistence. Exact error replay applies only after the entire document is retained within the cap, validated and durably settled with own ACK. Partial/read failure, oversize, malformed or complete-absent bodies follow the disposition table and local refusal precedence; do not promise truncated-byte preservation or return a partial upstream body as certified evidence. Unassociated error wrapping is unchanged. Required cases: non-fallback final error, exhausted single/multiple accounts, later success, successor budget/authority/recording refusal, unsafe-header stripping and own-ACK hold/failure.

ACK barrier must not depend on unbounded `reader.cancel()`/cleanup; terminal persistence error wins over cleanup errors.

Unsupported refresh: common core retry fetch still routes through same helper; test through core seam that returned mutated credentials cannot emit selected successor POST. Dynamic API-key full-route case401/403 has no legitimate refresher and tests this. Existing unassociated OAuth refresh success remains compatibility regression, not selected accounting support. Account fallback uses real persisted two-account route+HTTP failure with exact usage; predecessor own terminalACK+policy eligibility+successor budget/authority required. A refresh token HTTP call is not an inference charge.
